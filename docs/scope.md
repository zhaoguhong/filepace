# First-version scope and verification

## Agreed product rules

- macOS + Windows; Tauri + Rust + React.
- Single-pane and left/right split layouts inside each window. Each pane has independent tabs and navigation.
- Tabs reorder within a window and can be moved to a new window. Cross-window tab drag is deferred.
- New tabs and windows start at the current location. Closing the last tab of one split pane returns to a single pane. Closing the last tab of a single pane closes its window.
- List View is the default for new tabs and windows unless changed in Settings. View controls are ordered List, Column, Icon. Restored tabs retain their saved views.
- File operations belong to the application, not the originating tab.
- Default delete means system trash, with no fallback to permanent deletion.
- Windows installation must work as a standard user without administrator credentials.
- Sidebar → tabs → path/filter bar → toolbar → files → status/tasks.

## Smart storage diagnosis

- Directory Analysis offers diagnosis through installed Codex, Claude Code, OpenCode, and DeepSeek Harness (`dsh`) CLIs. Discovery checks absolute PATH entries, common installation directories, and macOS app-bundled Codex locations. A separate executable path can be saved for each tool. Windows npm `.cmd` shims resolve to known JavaScript entry points and Node, without passing prompts or paths through `cmd.exe`.
- Diagnosis can start without a separate scan action. It automatically scans if needed, reuses a current-scope snapshot, and offers an explicit rescan option. Cancellation covers both preparation and agent execution, including a scan that completes after cancellation; empty and failed scans do not start an agent. Publishing a diagnosis's own snapshot preserves its report and errors, while external scans and scope changes invalidate the old request.
- Directions include overview, cleanup, organization, understanding, and custom. Presets accept supplemental requirements; custom requires nonblank text. Rust validates the direction and 2,000-character limit before invoking the CLI, attaches the request to the report, and constrains understanding-mode finding categories to `review`. Requirements adjust the analysis focus without expanding scope or tool permissions.
- Diagnosis uses the latest successful scan cached on the Rust backend for that window and scan ID. Names, relative paths, category totals, bounded rankings, and the selected direction and requirements are supplied over stdin. File contents are not read. Model references must match backend-issued item IDs before Filepace supplies navigation targets; invalid, oversized, or incomplete reports are rejected.
- Each invocation runs in a disposable directory with restricted tools and without user project instructions or user plugins. Codex projects only model/connection settings from its user configuration and optional named profile while retaining its original auth home. Literal provider headers are passed in child environment variables rather than command-line arguments. Claude Code retains native user-level settings under safe mode. OpenCode projects JSON/JSONC connection settings into a private temporary config while preserving its auth data directory; legacy and standalone-server command paths are supported. Additional authentication plugins and provider packages are not generally supported.
- DeepSeek Harness uses a temporary, explicit composition of official model/session services with no file, shell, web, MCP, or user-plugin tools. It reads static connection rows from the selected profile (`headless` by default) and home patch, supports legacy `settings.yaml`, and uses the existing credential store plus a private temporary copy of `.env`. User expressions are not evaluated. Invalid/unsupported connection configuration stops diagnosis instead of switching providers. Original model configuration files are not changed. Authentication is handled by the installed tools, which can contact model services and consume account usage; this is not an offline-model guarantee.
- The UI distinguishes executable detection from authentication/connectivity, displays configured model/provider/source, and offers Codex and Harness profile selection. The tool list places detected commands without configuration errors first, commands requiring configuration fixes next, and missing commands last. Initial detection retains the saved tool if its executable and configuration are valid, otherwise selecting a detected tool without configuration errors. Explicit manual selections remain selected during subsequent detection so users can fix their configuration or command path. Scanning is scoped to Usage Analysis; completed scans show their time, a secondary Rescan button, and a primary Smart Diagnosis action.
- Stop, scope changes, rescanning, panel closure, and window destruction cancel diagnosis. The runner bounds input/output, times out after five minutes, drains stdin/stdout/stderr without blocking cancellation, and owns a Unix process group or Windows Job Object. Window destruction terminates registered processes synchronously. Cancellation arriving before job registration is retained. Reports remain available while navigating to a referenced file and returning to the same scan.
- Rust fixtures cover literal executable paths, metadata-only inputs, window/scan isolation, reference validation, all four output envelopes, transient errors, output limits, blocked pipes, cancellation, and process-tree termination. OpenCode fixtures cover both legacy runs and private-server flags, including cancellation during capability discovery.
- Browser tests cover all four agent selections, missing-command configuration, report navigation and retention, stop/error/retry, stale responses after scope changes, rescanning and panel closure, and the disabled browser preview. Light and dark layouts were visually inspected. The required frontend tests, production build, browser tests, and locked Rust tests passed.

## File organization

- Undo keeps up to 20 move and rename records in the current session. It checks item identities and original locations before restoring files. A merged move records the items it actually moved and preserves the destination folder's unrelated items. Earlier replacement items remain in the system trash.
- Search tries the platform index for the selected directory. It can scan the directory when the index is unavailable or misses items, and can stop between entries. Results are limited to 300 matches.
- Compression uses system tar when its output matches the selection and uses the ZIP library as a fallback. Extraction accepts regular files and folders, validates entry paths, and stages the result before committing it. A ZIP can contain up to 250,000 entries.
- Tests cover undo conflicts and retry, replaced identities, nested search, ZIP round trips, and path traversal rejection. Browser tests cover search result navigation, system light and dark mode, and saved themes.

## v0.7.0 directory analysis and transfer hardening

- Split panes use a one-pixel themed divider with a nine-pixel pointer target. The full-width active-pane stripe is removed; the small current-pane badge remains. Pointer capture, keyboard resizing, equal-width reset, selection independence, light/dark themes, and legacy single-pane sessions are covered by browser/unit tests.
- Directory reads stream batches of at most 256 entries or about 80 ms, with a complete final snapshot. Browser tests cover partial results, selection preservation, ten-thousand-entry virtualization, shared-pane request deduplication, cancellation after the last subscriber leaves, ignored late output, and refresh preserving the old complete snapshot. Cancellation takes effect between OS calls; blocked filesystem calls remain subject to OS/network delays.
- A local macOS warm-metadata benchmark of native enumeration (excluding fixture creation, IPC and rendering) found first batches at 1.7 ms / 1.2 ms and completion at 45 ms / 436 ms for 10,000 / 100,000 files respectively. Both final counts and fixture bytes were checked. These timings are not cold-cache or network-drive guarantees.
- Each window retains eight scan scopes, with backend scan-ID reuse for diagnosis. Rescanning replaces a scope's old ID; caches stay isolated between windows. Snapshots show dates and are marked stale after five minutes or overlapping directory-change events. Diagnosis refreshes stale snapshots. Filesystem watchers do not guarantee recursive freshness; scan snapshots are explicitly historical.
- Analysis layout places large files beside classification and removes the duplicate diagnosis promotion. Browser tests check first-screen file visibility and fresh metadata before diagnosis.
- Transfer intent journals are flushed before staging, replacement, commit and source cleanup. Restarted tasks are review notices with retained paths, never automatic resume, cleanup or undo. Clearing notices deletes only their journals. Native tests check restart reporting without touching source, target, stage or backup, completed-journal cleanup, and transfer bytes.
- Windows native CopyFileEx copies preserve alternate streams and file attributes, support progress cancellation, and keep fail-if-existing semantics. Sparse sources request sparse copying and reject loss of the sparse attribute before deleting sources. Destination ACLs use native inheritance rather than cloning source security descriptors. Windows-only fixtures cover alternate streams, read-only flags, sparse allocation and byte preservation.
- The main window delegates task rendering, split resizing and session normalization to separate modules. Saved sessions with only tabs/active remain compatible. Live selections are not mutated when saving a session.
